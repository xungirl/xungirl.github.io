AI Application Project Report · 2026

TicketCoach

An LLM Practice Gym and Coaching Agent for Cloud Support Trainees

Jiaju Zhang · Northeastern University · github.com/xungirl/TicketCoach

Code

Abstract - New cloud-support hires need practice on angry, messy tickets before they meet real customers. TicketCoach is a FastAPI web app that turns a ticket into a roleplay script with a 3-step LLM pipeline, lets a trainee chat with an AI customer, scores the session per dimension, and adds an AI coach: a bounded tool-calling agent over a hand-rolled hybrid index of 30 real Alibaba Cloud help docs and the trainee's own score history. After a real outage took the deployed demo down, every model call was moved behind one gateway with a cross-provider fallback chain and a circuit breaker. Offline, 47 tests pass and BM25 retrieval reaches Hit@1 0.933 and Hit@5 0.967 on 30 hand-labeled questions. A sabotage run showed the eval harness catches a lazy agent: a good session's score fell from 93 to 30. The coach eval and the vector half of retrieval have not been run yet.

Index Terms - LLM application, tool-calling agent, hybrid RAG, BM25, LLM gateway, circuit breaker, eval harness, FastAPI.

I. The problem

Practice that looks like the real queue

Support trainees learn most from tickets that are vague, emotional and full of typos, and from feedback on what they missed. TicketCoach generates such a ticket, extracts a roleplay script with scoring criteria (regenerating once if the QA review scores below 60), and plays the customer from the script's actor_prompt: the customer gets angrier or calmer depending on the reply. A finished session is scored per dimension with what went well and which challenge points were missed (roleplay screenshot, score report). Teams can also import real tickets as JSON, JSONL, CSV or text; the normalization prompt must not invent missing fields.

A. Design

Gateway. core/llm.py tries LLM_MODEL, then LLM_FALLBACK_MODELS, which may cross to Gemini. A retired model (404), exhausted quota (403), rate limit, timeout or 5xx moves to the next entry; an overdue-bill 400 Arrearage skips every model on that account. A model that returned 404/403 is skipped for 10 minutes, and when all are cooling down a single half-open probe is sent. Streams fall back only before the first token. Tokens, p50/p95 latency and estimated cost are served at /api/metrics, and LLM_CHAOS_RATE injects failures.

Coach. The agent has 5 tools with pydantic-validated arguments and a step budget of 6 that ends in one forced call with tools disabled. Tools never take a trainee ID: identity comes from an HMAC-signed token, so a prompt-injected "show me user X" has nothing to call. Citations like [D3] that no tool returned are stripped. read_help_doc fetches only allowlisted hosts that a search already returned.

Retrieval. Help pages are split by heading into 580 chunks. BM25 uses CJK bigrams with no segmenter; vectors are a numpy dot product; RRF merges them, and search falls back to BM25 if embeddings fail. Embeddings deliberately never cross providers, since vectors from different models cannot be compared. Pydantic schemas check every structured output, and the model repairs a violation once.

B. Results

The README records only measured numbers. The retrieval eval also found one wrong label (no doc answers "how do I configure the origin host"), which was replaced. One paraphrase ("ping得通" vs. the doc's "能ping通") still misses with keywords alone, the gap the vector half is meant to close. In the eval harness, the LLM judge's score did not drop under the lazy-transcript sabotage; the harness README explains this is expected, because the judge rates whether the examiner was fair.

C. Limits

The deployed demo is down. In 2026-10 qwen3-max was retired (404) and the DashScope account went into arrears, which blocks every model and the embedding API at once; the gateway was built in response, and funding the account (or adding a Gemini key) is still listed as a next step. Because embeddings were blocked, the vector and hybrid halves of retrieval are not measured, the 15-case coach eval and its chaos drill are written but not run, and only the 6 evaluate cases of the 24-case pipeline set have recorded runs. Memory is SQLite on the container's disk, so it does not survive a Cloud Run redeploy, and quotas and metrics assume one instance. The knowledge base is 30 hand-picked docs, not the whole help center. The gateway, structured output, RAG coach and latency work are on the agent-upgrade branch, not yet merged into main.
