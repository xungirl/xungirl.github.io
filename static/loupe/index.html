Loupe: A Flight Recorder for AI Agents

Jiaju (Jensen) ZhangKhoury College of Computer Sciences, Northeastern University, Seattle
github.com/xungirl/loupeGo · SQLite · React · Python

Abstract—Coding agents spend most of their budget in places nobody looks at: retried tool calls, rewrites of the same file, subagents that run long. Loupe records every model call and tool call as a span, rebuilds the multi-agent tree even when spans arrive late or out of order, flags failure patterns, and shows the run as a waterfall, an agent tree and a live tail. The Go ingest path commits 137,172 spans/s with batching (2.49× one span per request) and sheds overload with HTTP 429 while writing every accepted span. At 1.02 M stored spans a typical trace opens in 0.38 ms (p50). We also ran a preregistered harness experiment on a real model, 216 runs for ¥1.42: a restate-first prompt and a planner/coder/reviewer team gave no detectable pass-rate gain at a 98.6 % ceiling, and cost 1.6–1.7× the tokens.

Index Terms—observability, OpenTelemetry GenAI, backpressure, trace assembly, agent harness, preregistration.

I.Introduction

An agent run is a tree: a main agent calls the model, calls tools, and spawns subagents that do the same. When a run is slow or expensive, the transcript alone rarely says why. Distributed-tracing systems answer this question for microservices, and the OpenTelemetry GenAI conventions already name the attributes. Loupe applies that model to agents and adds detectors for the failure shapes agents have and services do not, such as editing the same file in a loop.

Loupe accepts spans from four sources: a Claude Code hook adapter, a small Python SDK, any OTLP/HTTP JSON exporter, and an offline importer for Claude Code transcripts that turns sidechains into subagents. All four go through the same ingest path in Fig. 1.

II.Ingest under pressure

B. Backpressure

To test overload we shrank the queue to 5,000 spans and sent 600 requests of 500 spans from 32 clients with retries disabled. In all three runs the server answered 574–578 requests with 429, the queue never exceeded its bound, peak memory stayed at 58–62 MB, and every accepted span reached the database (Table II).

A graceful stop drains the queue: in a test the real binary receives SIGTERM with 3,000 queued spans and an open live-tail connection, and all 3,000 end up on disk. A crash can lose at most one queue of acknowledged-but-uncommitted spans; clients that need durability pass ?wait=true.

III.Reading traces

Storage never waits for a parent span. The tree is assembled at query time from whatever has arrived: orphans stay visible and attach when their parent shows up, and cycles are broken. A trace shuffled 200 times assembles to the same tree. Table III lists read latency over HTTP at 1,017,547 spans in 24,201 traces.

IV.Failure detectors

Five rule-based detectors run per agent: repeated near-identical tool calls (loop), edit → failing test → edit cycles (rework), error streaks, no progress (stuck) and token burn (budget). Every finding links to the spans that triggered it. Thresholds were tuned on a training split of a 300-trace fault-injection corpus and scored once on the held-out half.

V.Harness experiment

"Agent = Model + Harness" suggests that, with the model fixed, cheap harness changes should matter. We tested two on 24 Python tasks with hidden tests: arm B adds a step where the model restates the task before coding, and arm C splits the work between a planner, a coder and a reviewer. Hypotheses, task set, analysis and a ¥4.50 cap were committed in PREREG.md before any real call; the cap is checked in code before every call.

The preregistration named a ceiling effect as a likely outcome, and it happened: the single agent already solves 98.6 % of the tasks, so neither change can show a benefit and both only add cost. Restating the task did not reduce rework here; descriptively it rose from 0.15 to 0.31 rewrites per run. A fair test of the restate idea needs harder, multi-file tasks.

VI.Limitations

  • All measurements come from one laptop over localhost (Apple M2, 8 cores).
  • The importer was tested on synthetic transcripts; unknown shapes are counted in its parse statistics instead of dropped.
  • OTLP is accepted as JSON only, and the server has no authentication; it binds to 127.0.0.1.
  • The experiment used one model and one family of easy tasks.

VII.Conclusion

Treating agent runs as traces works with ordinary backend tools: a bounded queue, one batching writer and query-time assembly handle 1 M spans on a laptop, and the same traces made a small harness study cheap to run and easy to audit. Next steps are harder tasks for the experiment, hand-labeled real runs for the detectors, and a columnar store for aggregates.
