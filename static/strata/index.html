strata: A Hybrid Lexical + Vector Search Database in Rust, Built From Scratch

Jensen Zhang
Northeastern University
github.com/xungirl/strata
Code ↗Benchmarks ↗Evidence ↓

Abstract—strata is a hybrid (lexical + vector) search database written from scratch in Rust over 10 stages: a BM25 engine, a durable segment store, exact dynamic pruning, its own HNSW, hybrid fusion, a sharded coordinator and its own Raft. Every stage is checked against the one before it. With Lucene's length quantization it reproduces Anserini's published BEIR BM25 numbers in 13 of 15 cells to 4 decimals; a 4-shard cluster gives the same metrics as one node to 6 decimals; and over 75 leader kills 0 of 53,130 acknowledged writes were lost. Fusing BM25 with dense retrieval reaches nDCG@10 0.8051 on trec-covid. Everything was measured on one laptop.

Index Terms—inverted index, BM25, MaxScore, block-max WAND, HNSW, hybrid retrieval, scatter-gather, Raft, MCP, Rust.

I. The problem

Search engines are wrong in quiet ways

A search engine rarely crashes when it is wrong. A stemmer that differs from Lucene's moves nDCG@10 (the first gap to Anserini was up to 0.005 and came from the stemmer), a pruning bound that is slightly too tight drops a document, a shard with local IDF scores the same document differently, and a crash can lose a write that was already acknowledged. strata builds each layer against an oracle: the stage-1 in-memory index with exhaustive term-at-a-time scoring, cross-checked against pytrec_eval, Tantivy and Anserini, is what every later stage must reproduce.

II. Design

Lexical core and storage. The analyzer is UAX #29 tokenization, Lucene's 33 stopwords and an own port of Lucene's classic Porter stemmer (23,531/23,531 words match the official output). The durable index is a WAL with group commit, immutable mmap segments with an FST term dictionary and bit-packed 128-doc blocks, tombstones, background merges of adjacent segments and Arc snapshot readers. Batching 1,000 docs per fsync raises scifact ingest from 224 to 12,224 docs/s.

Query engine. Block-max WAND and MaxScore both return exactly the exhaustive top-k; a proptest checks them bit-identical against term-at-a-time over random corpora with merges, deletes and filters. MaxScore is the default.

Vectors. An own HNSW with hand-written NEON f32 distances, int8 quantization with f32 rescoring and filtered search runs over locally computed bge-small embeddings.

Distribution. The coordinator routes writes by FNV-1a(id) % shards and searches in the two rounds of Fig. 1; slow shards get a deadline and a hedged request to the next replica. A shard is replicated by an own Raft, written as a pure state machine and tested in 300 randomized simulated schedules that catch 6/6 injected bugs.

III. Results

Exactness. The disk engine and both pruning algorithms write byte-identical run files to stage 1 on all five datasets. The 4-shard cluster matches single-node metrics to 6 decimals with identical top-100 lists; the 133 of 2,306 top-1000 lists that differ only swap equal-score documents at rank 1000.

Crashes. 100 kill -9s during writes, flushes and merges: 113,480 acked adds and 2,639 acked deletes, 0 lost, 0 resurrected; a negative control that acks before writing is caught (147 lost). Raft failover took p50 261 ms, max 782 ms.

Quality. Fusion is best on three of five datasets (Table I); on fiqa and scidocs dense alone wins. RRF beats BM25 by +0.04 to +0.21 (p ≤ 1e-5 on all five). The MS MARCO cross-encoder re-ranker lowered nDCG@10 versus RRF on 4/5 datasets, and that result is kept.

Service. Hedging after 5 ms brought p99 with a slow replica from 56.3 ms back to 9.3 ms for 1.67% extra shard requests. As an MCP memory server on LoCoMo, BM25 recall reaches nDCG@10 0.494; an offline hybrid with bge-small reaches 0.534.

IV. Limits

Every process ran on one 8-core laptop shared with other workloads, so there is no real network and the load generator competed with the server. Durability was tested against process kills only, not power loss, and macOS fsync is not F_FULLFSYNC. The Raft shard is not yet behind the coordinator and has no snapshots or log compaction. Pruning gains are modest on these small corpora, and block-max WAND was slower than exhaustive search. The Tantivy comparison is not a claim that strata is faster. The Docker and compose files were written but never run.
